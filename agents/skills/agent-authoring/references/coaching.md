# Coaching

Apply the parent Skill's coaching behavior using these detailed interaction mechanics.

## Coaching Approach

Default to:

- 2–6 short lines;
- one main question or task;
- the smallest useful explanation or example;
- one clear next step.

Help the user make meaningful decisions rather than making consequential choices silently.

Do not require the user to attempt an answer before explaining a straightforward concept.

## Progressive Guidance

Escalate only as much as needed:

1. **Point** — identify the issue.
2. **Narrow** — focus the decision.
3. **Explain** — provide the minimum reasoning needed.
4. **Wording fragment** — offer a small concrete formulation.
5. **Rewrite** — produce the full revision when that becomes useful.

Do not jump to a complete rewrite when a smaller intervention would allow the user to make the consequential decision themselves.

## Iteration

After each meaningful user response:

- acknowledge what it resolves;
- identify the remaining important issue;
- continue with the smallest consequential next step.

Do not introduce unrelated questions while the current issue remains unresolved.

## Re-read and Context-Loss Check

Apply the parent Skill's Context-Loss Check whenever revisiting accepted content.

During iterative coaching, explicitly compare the proposed revision with the earlier accepted version when simplification, merging, or rewriting could remove meaningful context.

Pay particular attention to:

- user intent and accepted decisions;
- constraints and exceptions;
- authority and precedence;
- scope and ownership;
- safety and compatibility;
- rationale that materially changes rule application;
- context distinguishing similar concepts.

Shorter wording is not an improvement when meaningful behavior or distinctions are lost.

If context loss is found, surface or restore it before moving to the next issue.

After resolving local wording issues, check related artifacts when relevant for:

- ownership;
- stale instructions;
- routing;
- terminology;
- workflow;
- precedence.

## Leaving Coaching

Do not force coaching when the user asks for:

- a direct answer or explanation;
- a complete review;
- drafting or rewriting;
- implementation whose important decisions are already defined.

Switch naturally to the requested mode.

Return to coaching only when a consequential unresolved decision genuinely requires it.
