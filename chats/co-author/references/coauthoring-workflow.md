# Co-Authoring Workflow

Use this reference for substantial document creation or restructuring.

The workflow has three stages:

1. Understand
2. Structure and Draft
3. Whole-Document Review

These are tools, not mandatory gates. Skip, combine, or revisit stages based on the task.

## 1. Understand

### Goal

Close only the context gaps that prevent useful drafting or create material risk.

### Establish

Determine what is relevant from:
- document type;
- purpose;
- primary audience;
- desired outcome;
- required format or template;
- constraints;
- existing source material;
- important stakeholders;
- technical dependencies; and
- unresolved decisions.

Use information already available before asking questions.

Do not request information merely because it appears in this list.

### Context Gathering

When substantial context is missing, let the user provide it in whatever form is most efficient:
- shorthand answers;
- rough notes;
- unstructured information dumps;
- existing documents;
- source files;
- relevant discussions; or
- connected sources when available.

Organise the information internally rather than requiring the user to organise it first.

Track:
- confirmed information;
- assumptions;
- unresolved questions; and
- decisions that affect later sections.

### Questions

Ask only questions whose answers could materially change the document.

Prefer questions about:
- unclear goals;
- competing requirements;
- consequential edge cases;
- constraints;
- trade-offs;
- ownership;
- compatibility; and
- expected reader behaviour.

Batch related questions when efficient.

Do not block useful progress on questions that can reasonably remain unresolved.

## 2. Structure and Draft

### Choose the Approach

Infer the lightest suitable mode.

**Direct**

Use when intent and content are sufficiently clear.

Draft or edit immediately.

**Collaborative**

Use when important content or decisions remain uncertain.

Discuss the uncertain parts, then draft.

**Rigorous**

Use when the document is consequential, complex, or likely to be reviewed by multiple stakeholders.

Use explicit structure refinement, trade-off analysis, whole-document review, and reader testing.

Modes can change during the task.

### Document Structure

If an established template exists, prefer it.

If structure is unclear, propose a concise structure appropriate to the document and explain only choices that materially affect the result.

Do not force generic sections into documents where they add no value.

Prefer working on substantive or uncertain sections before summaries.

### Section Workflow

For each section, use only the steps that add value:

1. identify unresolved decisions;
2. ask focused questions if necessary;
3. surface useful considerations or alternatives;
4. let the user decide consequential choices;
5. draft;
6. refine from feedback.

Do not require brainstorming before obvious content.

Do not require the user to select numbered options when normal feedback is sufficient.

### Brainstorming

Use brainstorming when the user is exploring possibilities or important content may be missing.

Generate enough options to expose meaningful alternatives without overwhelming the user.

Prioritise:
- forgotten context;
- edge cases;
- stakeholder concerns;
- trade-offs;
- assumptions;
- dependencies; and
- consequences.

Avoid padding the list to meet an arbitrary number.

### Drafting

Draft from the decisions and evidence already established.

Do not introduce new commitments, requirements, or technical assumptions without making them visible.

When an unresolved issue does not block drafting, mark it clearly rather than inventing an answer.

### Refinement

Prefer surgical edits.

When the user requests a local change, preserve unaffected content unless a broader correction is necessary.

Learn from feedback about:
- preferred level of detail;
- terminology;
- structure;
- tone;
- what the audience already knows; and
- what the user considers unnecessary.

Apply those preferences to later sections.

## 3. Whole-Document Review

Use this stage for substantial documents once most substantive content exists.

Review the document as a single artifact.

Check for:

### Flow

- Does the order match how readers need to understand the topic?
- Are prerequisites introduced before they are used?
- Are conclusions supported by preceding material?

### Completeness

- Are important decisions explicit?
- Are constraints and dependencies visible?
- Does critical information exist only in the conversation?
- Are unresolved issues distinguishable from settled decisions?

### Consistency

- Are terms used consistently?
- Do sections contradict one another?
- Do requirements, examples, and conclusions agree?

### Signal

Look for:
- repetition;
- generic filler;
- unnecessary background;
- over-explanation;
- duplicated conclusions; and
- content that does not help the reader act or decide.

Recommend deletion when content can be removed without losing important meaning.

### Final Transition

When ambiguity or reader comprehension remains a material risk, use `reader-testing.md`.

Otherwise perform a final quality check and complete the document.
